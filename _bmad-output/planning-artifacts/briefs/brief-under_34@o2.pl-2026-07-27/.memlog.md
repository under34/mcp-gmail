topic: Usługa MCP server dla Gmaila
updated: 2026-07-27T13:10
---

- (decision by user) Rozpoczynamy od zera z pomysłem na usługę MCP server dla Gmaila.
- (direction by user) Aplikacja automatyzuje podsumowania maili Gmaila: Google Cloud OAuth i Gmail API, skrypt Python pobierający maile, serwer MCP z endpointem pobierania i analizy, zewnętrzne API AI do podsumowań, harmonogram cykliczny, testy lokalne i wdrożenie hostingowe. Priorytety: sprawność i minimalizacja kosztów AI.
- (assumption by coach) Rekomendowany MVP: pojedynczy użytkownik lub wewnętrzna organizacja Google Workspace, scope gmail.readonly, przetwarzanie jedynie nowych wiadomości po filtrze i bez trwałego przechowywania ich treści.
- (risk by coach) Publiczna aplikacja z dostępem do treści Gmaila wymaga weryfikacji OAuth restricted scope; przesyłanie treści do zewnętrznego AI może wymagać dodatkowej oceny bezpieczeństwa.
- (direction by coach) Warstwa AI ma minimalizować koszt przez przetwarzanie wyłącznie nowych lub zmienionych wiadomości, oczyszczanie treści, krótki wynik strukturalny i mały model dla większości zadań; tryb batch tylko opcjonalnie dla asynchronicznego dziennego podsumowania.
- (decision by user) Wybrano warsztatowy tryb pracy zgodny z metodą BMad.
- (decision by user) MVP będzie narzędziem osobistym dla jednego konta Gmail.
- (decision by user) MVP udostępni oba tryby: codzienny automatyczny digest oraz narzędzia MCP do zapytań ad hoc o podsumowania.
- (decision by user) Analizowane będą wyłącznie wiadomości spełniające konfigurowalne filtry. Domyślnie: Inbox z wyłączeniem Promotions i Social; konfiguracja obejmie nadawców, etykiety i słowa kluczowe.
- (decision by user) Wynik analizy pojedynczego maila w MVP: zwięzłe streszczenie, priorytet oraz lista konkretnych działań. Terminy i proponowane odpowiedzi są poza zakresem MVP.
- (decision by user) Automatyczny digest MVP będzie uruchamiany raz dziennie rano.
- (decision by user) Poranny digest będzie zapisanym wynikiem dostępnym przez MCP; MVP nie wysyła e-maila z digestem.
- (decision by user) MVP będzie działać lokalnie na komputerze użytkownika; OAuth użyje lokalnego redirectu, harmonogram systemowego cron, a dane i tokeny pozostaną lokalnie.
- (decision by user) Kryterium sukcesu MVP: poranny digest wiarygodnie prezentuje najważniejsze nowe maile oraz wynikające z nich działania.
- (question by user) Użytkownik wskazał OpenAI API oraz Claude Code; wymaga doprecyzowania, czy Claude ma być środowiskiem tworzenia aplikacji, czy API Anthropic do podsumowań maili.
- (decision by user) MVP użyje dwóch dostawców do podsumowań: OpenAI API oraz Anthropic Claude API.
- (decision by user) OpenAI API będzie domyślnym dostawcą AI, a Anthropic Claude API ręcznie wybieraną alternatywą do porównania jakości.
- (decision by user) Lokalnie przechowywane będą wyłącznie identyfikatory Gmaila, hashe, metadane i podsumowania; pełna treść maili nie będzie utrwalana.
- (event by coach) Brief przygotowany do przeglądu. Wszystkie merytoryczne decyzje z dziennika uwzględniono w brief.md; addendum nie jest potrzebne.
